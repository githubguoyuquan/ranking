# 话题动态指标方案

## 现在怎样生成

新建或修改话题时，API 在项目内根据运营选择的榜单证据类型生成指标方案，不请求任何收费 AI 服务，也不需要 API Key。

- 客观榜：强调可核验结果、记录完整度、来源一致性。
- 半客观榜：强调有据成果、独立认可、证据质量。
- 主观趋势榜：强调当前关注度、关注增势、来源多样性。

这套方案不包含足球、音乐、商品等业务类别词表，也不会把播放量强加给球星榜。话题名称只用于方案说明；项目不会假装本地规则已经理解任意自然语言中的复杂业务含义。

## 运营怎么操作

1. 新建话题时选择最符合榜单用途的“榜单类型”。
2. 在新建版本区域检查自动带入的指标、权重和“必须有数据”标记。
3. 展开“数据口径与建议来源”，确认每个实体都能按相同时间窗、相同比较范围取数。
4. 如业务定义更具体，在创建版本前直接修改权重和必需项。
5. 按页面显示的英文 `metricKey` 导入每个实体的 0–100 分真实数据，再运行榜单。

指标方案只定义比较口径，不会根据名称虚构指标值。所有新方案以 `generatedBy: local_algorithm` 保存到 `Topic.metricPlan`；刷新页面不会丢失。

## 旧数据兼容

以前保存的 `generatedBy: openai` 方案只作为历史数据读取，不会触发网络请求。没有 `metricPlan` 的更早话题继续按其既有版本规则展示。向量算法已改为本地实现，升级后如使用 ES/Qdrant，应执行一次全量重建索引，避免新旧向量混用。
